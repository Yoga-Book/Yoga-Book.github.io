= Contributing
:description: How to contribute reproducible fixes and hardware reports to Yoga Book Linux.

Contributions and reproducible hardware reports are welcome.

== Find the owning project

Start with xref:projects.adoc[the project map], then search that repository's existing issues and read its local contribution guidance. Driver, package, and application defects should be reported to the component that owns them.

For system-wide behavior or help collecting evidence, begin with https://github.com/Yoga-Book/Yoga-Book-Validator[Yoga Book Validator].

== Make the result reproducible

A useful report or change records:

* the exact hardware model and software revisions;
* the smallest reliable reproduction procedure;
* the logs or test output that support the conclusion;
* the distinction between build, VM, and physical-device evidence; and
* any recovery steps needed when testing the change.

== Improve this site

Organization-level navigation and shared guidance live in the https://github.com/Yoga-Book/Yoga-Book.github.io[site repository]. Project-specific implementation documentation remains in the repository that owns it; this handbook summarizes cross-project workflows and links the authoritative source.

For a handbook change:

* identify the authoritative project document or physical evidence behind the statement;
* record a review date when summarizing information that can become stale;
* distinguish YB1-X91L evidence from assumptions about other variants;
* distinguish a build, VM result, automated result, functional check, and physical observation;
* give destructive or state-changing commands an explicit warning, target, prerequisite, and recovery path;
* include expected output or a clear success condition where practical;
* link to the owning project instead of duplicating volatile version lists; and
* never publish credentials, serial numbers, private firmware, or unreviewed Validator bundles.

Build and verify the generated site before submitting a change:

[source,console]
----
npm ci
task check
----

`task check` runs the strict Antora build and verifies generated internal links and anchors.
